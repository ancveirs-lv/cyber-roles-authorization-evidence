# Pilnā kiberdrošības vārdnīca

Šajā lapā attēloti visi mašīnlasāmās datu kopas kanoniskie termini. Statuss raksturo termina lietojumu; tas nevērtē cilvēkus un nedod atļauju testēt.

## Aktori un identitātes apzīmējumi

<a id="term-hacker"></a>
### Hakeris

<span class="term-status">established_with_context</span>

Plašs kultūras vai tehnisks apzīmējums, kura nozīme atkarībā no avota un konteksta svārstās no zinātkāra, prasmīga sistēmu pētnieka līdz neatļautam lietotājam.

**Atļaujas robeža:** Apzīmējums pats par sevi nedod atļauju testēt sistēmu.

**Avoti:** [Internet Users' Glossary — RFC 1392](https://www.rfc-editor.org/rfc/rfc1392.html), [Hacker — CSRC Glossary](https://csrc.nist.gov/glossary/term/hacker), [Hacker — The Jargon File](https://www.catb.org/jargon/html/H/hacker.html), [Hacker Ethics](https://www.ccc.de/en/hackerethik)

<a id="term-cracker"></a>
### Krekeris

<span class="term-status">historical_or_community_jargon</span>

Vēsturisks kopienas termins personai, kas pārvar drošības aizsardzību; dažkārt lietots arī programmatūras aizsardzības apiešanai.

**Atļaujas robeža:** Termins nenosaka pilnvarojumu; jāapraksta faktiskā rīcība.

**Avoti:** [Internet Users' Glossary — RFC 1392](https://www.rfc-editor.org/rfc/rfc1392.html), [Cracker — The Jargon File](https://www.catb.org/jargon/html/C/cracker.html)

<a id="term-attacker"></a>
### Uzbrucējs

<span class="term-status">established</span>

Persona, kas mēģina izmantot ievainojamības vai citādi kompromitēt sistēmas drošību.

**Atļaujas robeža:** Parastā lietojumā uzbrukuma darbība ir pretinieka rīcība; autorizēta imitācija jānorāda atsevišķi.

**Avoti:** [Attacker — CSRC Glossary](https://csrc.nist.gov/glossary/term/attacker)

<a id="term-threat_actor"></a>
### Apdraudējuma aktors

<span class="term-status">established</span>

Persona vai grupa, kas saistīta ar darbībām, kuras rada kiberdrošības apdraudējumu.

**Atļaujas robeža:** Piesaistei konkrētam aktoram vajadzīgi pierādījumi un norādīts pārliecības līmenis.

**Avoti:** [Threat Actor — CSRC Glossary](https://csrc.nist.gov/glossary/term/threat_actor)

<a id="term-hacktivist"></a>
### Haktīvists

<span class="term-status">established_with_context</span>

Aktors, kas kiberaktivitāti saista ar politisku vai sociālu mērķi.

**Atļaujas robeža:** Motivācija neapliecina darbības likumību, atribūciju, patiesumu vai samērīgumu.

**Avoti:** [ENISA Threat Landscape 2025](https://www.enisa.europa.eu/publications/enisa-threat-landscape-2025)

## Profesionālās lomas

<a id="term-security_researcher"></a>
### Drošības pētnieks

<span class="term-status">established_with_context</span>

No konteksta atkarīgs apzīmējums personai, kas pēta kiberdrošību vai ievainojamības; formālai pētnieka lomai un ievainojamības atradēja lomai var būt atšķirīgi mandāti.

**Atļaujas robeža:** Lomas nosaukums pats par sevi neatļauj testēt konkrētu trešās personas sistēmu.

**Avoti:** [European Cybersecurity Skills Framework — Role Profiles](https://www.enisa.europa.eu/publications/european-cybersecurity-skills-framework-role-profiles), [CERT Guide to Coordinated Vulnerability Disclosure](https://certcc.github.io/CERT-Guide-to-CVD/tutorials/terms/cvd/), [Hacker Ethics](https://www.ccc.de/en/hackerethik)

<a id="term-ethical_hacker"></a>
### Ētiskais hakeris

<span class="term-status">established_with_context</span>

Plaši atpazīstams, bet no konteksta atkarīgs apzīmējums; ENISA Ethical Hacker min kā alternatīvu nosaukumu Penetration Tester profilā, bet kopienas lietojums var būt plašāks.

**Atļaujas robeža:** Ētisks nolūks neaizstāj tvērumu, noteikumus un juridisku pilnvarojumu.

**Avoti:** [European Cybersecurity Skills Framework — Role Profiles](https://www.enisa.europa.eu/publications/european-cybersecurity-skills-framework-role-profiles)

<a id="term-penetration_tester"></a>
### Penetrācijas testētājs

<span class="term-status">established</span>

Speciālists, kurš veic plānotu drošības pārbaudi noteiktā tehniskā tvērumā un saskaņā ar iesaistes noteikumiem.

**Atļaujas robeža:** Pilnvarojums parasti izriet no līguma, darba uzdevuma un iesaistes noteikumiem.

**Avoti:** [European Cybersecurity Skills Framework — Role Profiles](https://www.enisa.europa.eu/publications/european-cybersecurity-skills-framework-role-profiles), [Rules of Engagement — CSRC Glossary](https://csrc.nist.gov/glossary/term/rules_of_engagement), [Red Teaming](https://www.crest-approved.org/cyber-service-categories/red-teaming/), [Commission Delegated Regulation (EU) 2025/1190 on threat-led penetration testing](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:32025R1190)

<a id="term-incident_responder"></a>
### Kiberincidentu reaģētājs

<span class="term-status">established</span>

Speciālists, kurš analizē un ierobežo kiberincidentus, izskauž apdraudējumu un atbalsta atjaunošanu.

**Atļaujas robeža:** Piekļuve un rīcība izriet no organizācijas incidentu vadības mandāta un procedūrām.

**Avoti:** [European Cybersecurity Skills Framework — Role Profiles](https://www.enisa.europa.eu/publications/european-cybersecurity-skills-framework-role-profiles), [CSIRT Services Framework v2.1](https://www.first.org/standards/frameworks/csirts/csirt_services_framework_v2.1)

<a id="term-digital_forensics_investigator"></a>
### Digitālās kriminālistikas izmeklētājs

<span class="term-status">established</span>

Speciālists, kurš ar dokumentētām metodēm iegūst, saglabā, analizē un apraksta digitālos pierādījumus.

**Atļaujas robeža:** Atļauto rīcību nosaka mandāts, pierādījumu apstrāde un juridiskais konteksts.

**Avoti:** [European Cybersecurity Skills Framework — Role Profiles](https://www.enisa.europa.eu/publications/european-cybersecurity-skills-framework-role-profiles)

<a id="term-cyber_threat_intelligence_specialist"></a>
### Kiberdraudu izlūkošanas speciālists

<span class="term-status">established</span>

Speciālists, kurš apkopo, novērtē un komunicē informāciju par kiberdraudiem, norādot avotus un pārliecības līmeni.

**Atļaujas robeža:** Izlūkošanas novērtējums pats par sevi neatļauj mijiedarboties ar pretinieka infrastruktūru.

**Avoti:** [European Cybersecurity Skills Framework — Role Profiles](https://www.enisa.europa.eu/publications/european-cybersecurity-skills-framework-role-profiles)

## Komandu funkcijas

<a id="term-red_team"></a>
### Red Team

<span class="term-status">established</span>

Autorizēta grupa, kas imitē pretinieka spējas, lai novērtētu organizācijas novēršanas, atklāšanas un reaģēšanas spējas.

**Atļaujas robeža:** Darbību ierobežo mērķi, tvērums un iesaistes noteikumi.

**Avoti:** [Red Team — CSRC Glossary](https://csrc.nist.gov/glossary/term/red_team), [Rules of Engagement — CSRC Glossary](https://csrc.nist.gov/glossary/term/rules_of_engagement), [Adversary Emulation and Red Teaming](https://attack.mitre.org/resources/get-started/adversary-emulation-and-red-teaming/), [Red Teaming](https://www.crest-approved.org/cyber-service-categories/red-teaming/), [Commission Delegated Regulation (EU) 2025/1190 on threat-led penetration testing](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:32025R1190)

<a id="term-blue_team"></a>
### Blue Team

<span class="term-status">established_with_context</span>

Aizsardzības puse vingrinājumā vai novērtējumā; plašākā operacionālā lietojumā tā var ietvert uzraudzību, atklāšanu, analīzi, reaģēšanu un citus aizsardzības uzdevumus.

**Atļaujas robeža:** Precīzie pienākumi organizācijās atšķiras un var pārklāties ar SOC, CSIRT, incidentu reaģēšanu un inženieriju.

**Avoti:** [Blue Team — CSRC Glossary](https://csrc.nist.gov/glossary/term/blue_team), [Commission Delegated Regulation (EU) 2025/1190 on threat-led penetration testing](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:32025R1190)

<a id="term-purple_teaming"></a>
### Purple teaming

<span class="term-status">established_with_context</span>

Sadarbības prakse, kurā ofensīvie paņēmieni un aizsardzības novērojumi tiek savienoti, lai uzlabotu atklāšanu un reaģēšanu.

**Atļaujas robeža:** Tā var būt darba metode vai formāla komanda; neviena forma nepaplašina autorizēto testa tvērumu.

**Avoti:** [Adversary Emulation and Red Teaming](https://attack.mitre.org/resources/get-started/adversary-emulation-and-red-teaming/), [Commission Delegated Regulation (EU) 2025/1190 on threat-led penetration testing](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:32025R1190)

<a id="term-white_team"></a>
### White Team

<span class="term-status">established</span>

Vingrinājuma kontroles funkcija, kas uzrauga noteikumus, koordinē drošību, novēro darbības un vērtē rezultātus.

**Atļaujas robeža:** White Team pārvalda vingrinājumu; tas nav tas pats, kas white-hat hacker.

**Avoti:** [White Team — CSRC Glossary](https://csrc.nist.gov/glossary/term/white_team)

## Organizatoriskās funkcijas

<a id="term-soc"></a>
### Drošības operāciju centrs (SOC)

<span class="term-status">established_with_context</span>

Spēja, kuras kodols ir nepārtraukta uzraudzība, atklāšana un notikumu analīze; triāžas, eskalācijas un reaģēšanas pienākumi ir atkarīgi no mandāta.

**Atļaujas robeža:** SOC darbinieki rīkojas organizācijas pienākumu un piekļuves kontroļu ietvarā.

**Avoti:** [Team Types Within the Context of Services Frameworks — Version 1.2](https://www.first.org/standards/frameworks/csirts/team-type_1.2)

<a id="term-csirt"></a>
### Datoru drošības incidentu reaģēšanas komanda (CSIRT)

<span class="term-status">established</span>

Komanda, kas noteiktai klientūrai nodrošina drošības incidentu saņemšanu, analīzi, koordinēšanu, mazināšanu un atjaunošanu.

**Atļaujas robeža:** Pilnvaras un klientūru nosaka komandas mandāts.

**Avoti:** [Team Types Within the Context of Services Frameworks — Version 1.2](https://www.first.org/standards/frameworks/csirts/team-type_1.2), [CSIRT Services Framework v2.1](https://www.first.org/standards/frameworks/csirts/csirt_services_framework_v2.1)

<a id="term-psirt"></a>
### Produktu drošības incidentu reaģēšanas komanda (PSIRT)

<span class="term-status">established</span>

Komanda, kas saņem un novērtē produktu ievainojamību ziņojumus un kopā ar atbildīgajām produktu funkcijām koordinē lēmumu, labošanu un publiskošanu.

**Atļaujas robeža:** Tās mandāts attiecas uz organizācijas produktiem un koordinētu produktu drošības procesu.

**Avoti:** [Team Types Within the Context of Services Frameworks — Version 1.2](https://www.first.org/standards/frameworks/csirts/team-type_1.2), [PSIRT Services Framework v1.1](https://www.first.org/standards/frameworks/psirts/psirt_services_framework_v1.1)

## Atļauja un pilnvarojums

<a id="term-authorised_testing"></a>
### Autorizēta drošības testēšana

<span class="term-status">established_with_context</span>

Drošības testēšana ar atļauju, kas nosaka mērķi, laiku, metodes, ierobežojumus, ziņošanas ceļu un atbildīgās puses.

**Atļaujas robeža:** Pilnvarojums ir ierobežots; darbība ārpus noteiktā tvēruma netiek automātiski aptverta.

**Avoti:** [Rules of Engagement — CSRC Glossary](https://csrc.nist.gov/glossary/term/rules_of_engagement), [Gold Standard Safe Harbor Statement](https://docs.hackerone.com/en/articles/8494525-gold-standard-safe-harbor-statement)

## Ievainojamību procesi

<a id="term-cvd"></a>
### Koordinēta ievainojamību atklāšana (CVD)

<span class="term-status">established</span>

Process ievainojamības informācijas saņemšanai, analīzei, koordinēšanai, novēršanai vai mazināšanai un publiskošanai starp iesaistītajām pusēm.

**Atļaujas robeža:** CVD nav universāla testēšanas atļauja; konkrēta programma var noteikt autorizētu pētniecību savā tvērumā.

**Avoti:** [CERT Guide to Coordinated Vulnerability Disclosure](https://certcc.github.io/CERT-Guide-to-CVD/tutorials/terms/cvd/), [Guidelines and Practices for Multi-Party Vulnerability Coordination and Disclosure](https://www.first.org/global/sigs/vulnerability-coordination/multiparty/guidelines-v1.1), [PSIRT Services Framework v1.1](https://www.first.org/standards/frameworks/psirts/psirt_services_framework_v1.1), [Koordinētas ievainojamību atklāšanas platformas BUJ](https://cvd.cert.lv/faq/answers/100), [ISO/IEC 29147:2018 Vulnerability disclosure](https://www.iso.org/standard/72311.html)

<a id="term-vulnerability_disclosure_policy"></a>
### Ievainojamību atklāšanas politika (VDP)

<span class="term-status">established</span>

Organizācijas publiska politika, kas apraksta ziņošanas kanālus, tvērumu, sagaidāmo pētnieka rīcību, ziņojumu apstrādi un bieži arī drošā patvēruma nosacījumus.

**Atļaujas robeža:** Piemērojamā politika var noteikt tās izdevēja piedāvātās atļaujas un drošā patvēruma robežas; to iedarbība ir atkarīga arī no izdevēja pilnvarām, trešo personu tiesībām, līgumiem un piemērojamajiem tiesību aktiem.

**Avoti:** [BOD 20-01 — Develop and Publish a Vulnerability Disclosure Policy](https://www.cisa.gov/news-events/directives/bod-20-01-develop-and-publish-vulnerability-disclosure-policy), [A File Format to Aid in Security Vulnerability Disclosure — RFC 9116](https://www.rfc-editor.org/rfc/rfc9116.html)

<a id="term-vulnerability_disclosure_program"></a>
### Ievainojamību atklāšanas programma (VDP)

<span class="term-status">established_with_context</span>

Organizācijas spēja saņemt, izvērtēt, koordinēt, novērst un komunicēt ievainojamību ziņojumus; politika ir viena programmas daļa.

**Atļaujas robeža:** Programma var publicēt atļauju vai drošā patvēruma solījumu; piemērojamā politika nosaka piedāvātās robežas, ievērojot izdevēja pilnvaras, trešo personu tiesības, līgumus un piemērojamos tiesību aktus.

**Avoti:** [CERT Guide to Coordinated Vulnerability Disclosure](https://certcc.github.io/CERT-Guide-to-CVD/tutorials/terms/cvd/), [Establishing a Coordinated Vulnerability Disclosure Program](https://www.cisa.gov/resources-tools/resources/establishing-coordinated-vulnerability-disclosure-program-work-security-researchers)

<a id="term-security_txt"></a>
### security.txt

<span class="term-status">established</span>

IETF definēts, mašīnlasāms teksta formāts, kas palīdz pētniekiem atrast organizācijas drošības kontaktu un ievainojamību politikas informāciju.

**Atļaujas robeža:** Faila esamība vai neesamība nedod un neatņem testēšanas atļauju.

**Avoti:** [A File Format to Aid in Security Vulnerability Disclosure — RFC 9116](https://www.rfc-editor.org/rfc/rfc9116.html)

<a id="term-bug_bounty"></a>
### Bug Bounty programma

<span class="term-status">established</span>

Programma, kas aicina iesniegt noteikumiem atbilstošus ievainojamību ziņojumus un piedāvā noteiktu finansiālu vai citu atlīdzību par kvalificējošiem atradumiem; ne katrs iesniegums kvalificējas atlīdzībai.

**Atļaujas robeža:** Pilnvarojumu un tiesības uz atlīdzību ierobežo programmas tvērums un noteikumi.

**Avoti:** [BOD 20-01 — Develop and Publish a Vulnerability Disclosure Policy](https://www.cisa.gov/news-events/directives/bod-20-01-develop-and-publish-vulnerability-disclosure-policy), [Koordinētas ievainojamību atklāšanas platformas BUJ](https://cvd.cert.lv/faq/answers/100), [Gold Standard Safe Harbor Statement](https://docs.hackerone.com/en/articles/8494525-gold-standard-safe-harbor-statement)

<a id="term-responsible_disclosure"></a>
### Atbildīga ievainojamību atklāšana

<span class="term-status">common_but_contested</span>

Vēsturisks un joprojām lietots ievainojamību ziņošanas apzīmējums, kas bieži paredz privātu paziņošanu pirms publiskošanas.

**Atļaujas robeža:** Apzīmējums nenosaka testēšanas atļauju, termiņus vai pilnu koordinācijas procesu.

**Avoti:** [CERT Guide to Coordinated Vulnerability Disclosure](https://certcc.github.io/CERT-Guide-to-CVD/tutorials/terms/cvd/), [Guidelines and Practices for Multi-Party Vulnerability Coordination and Disclosure](https://www.first.org/global/sigs/vulnerability-coordination/multiparty/guidelines-v1.1)

<a id="term-full_disclosure"></a>
### Pilnīga ievainojamības publiskošana

<span class="term-status">established_with_context</span>

Publiskošanas pieeja, kurā ievainojamības detaļas dara publiskas pirms labojuma pieejamības; publicēto detaļu apjoms un laiks atšķiras.

**Atļaujas robeža:** Termins neapliecina iepriekšēju atļauju ievainojamības atrašanai vai testēšanai.

**Avoti:** [Guidelines and Practices for Multi-Party Vulnerability Coordination and Disclosure](https://www.first.org/global/sigs/vulnerability-coordination/multiparty/guidelines-v1.1), [RFPolicy 2.0](https://dl.packetstormsecurity.net/papers/general/rfpolicy-2.0.txt)

## Kopienas žargons

<a id="term-white_hat_hacker"></a>
### Baltais jeb white-hat hakeris

<span class="term-status">established_with_context</span>

Neformāls apzīmējums personai, kas veic likumīgu un autorizētu aizsardzības drošības testēšanu.

**Atļaujas robeža:** Ar krāsas apzīmējumu nepietiek; izšķirošs ir konkrētais tvērums un noteikumi.

**Avoti:** [White hat — Cyber.gov.au glossary](https://www.cyber.gov.au/glossary/white-hat)

<a id="term-script_kiddie"></a>
### Script kiddie / skid

<span class="term-status">historical_or_community_jargon</span>

Noniecinošs kopienas apzīmējums personai, kuru uzskata par gatavu rīku lietotāju bez pietiekamas izpratnes.

**Atļaujas robeža:** Prasmju līmenis nenosaka, vai darbība ir atļauta.

**Avoti:** [Script Kiddies: What Are They and What Are They Doing?](https://www.giac.org/paper/gsec/244/script-kiddies-what-doing/100752)

## Komunikācijas lomas

<a id="term-public_commentator"></a>
### Kiberincidentu komentētājs

<span class="term-status">project_descriptive_category</span>

Aprakstoša komunikācijas loma personai, kas publiski skaidro kiberincidentus, bieži izmantojot publisku vai sekundāru informāciju.

**Atļaujas robeža:** Tā nav standarta operacionāla loma un nenozīmē piekļuvi izmeklēšanas pierādījumiem.

**Avoti:** [Effective communications in a cyber incident](https://www.ncsc.gov.uk/guidance/effective-communications-in-a-cyber-incident)
